# AI 친화적 보고서 작성과 검사

사용자가 제공한 원문·근거에서 보고서를 작성한다. 원문에 없는 수치, 계산 결과, 주체, 조건 또는 해석을 추가하지 않는다. 누락된 사실은 사용자에게 확인한다. 표를 일괄 삭제하거나 병합을 무조건 금지하지 않는다.

표·그림 상단 제목과 순서 표시, 단순 병합, 서술식 문장, 일관된 항목 표시, 불필요한 꾸미기 지양을 적용한다. 번호는 문서 구조 표시로만 사용한다. 보고서의 사실처럼 수치를 새로 생성하지 않는다. 공식 원칙을 근거로 한 검사와 자체 보완 규칙을 구분한다.

## 형식 선택

서술형을 무조건 우선하지 않는다. 독자가 해야 할 작업에 맞춰 단락마다 선택한다.

- 배경·근거·대안·판단·실패 조건을 연결해 설명할 때는 서술형을 쓴다.
- 독립적인 확인 항목·준비물·권한은 불릿 목록, 순서와 선행 조건이 중요한 절차는 번호 목록을 쓴다.
- 여러 대상의 동일 속성·정확한 값을 교차 비교하거나 조회할 때는 표를 유지한다. 제목과 순서 표시를 붙이고 병합은 단순하게 한다.
- 간단한 용어·설명은 목록과 표 모두 가능하다. 독자의 목적과 화면 조건을 근거로 선택한다.
- 한 문서에 서술형·목록·표를 혼합할 수 있다. 사용자가 명시한 형식은 우선한다.
- 빠진 값은 추정하지 말고 미제공임을 표시하며 필요한 질문을 남긴다. 형식 선택 이유와 사실 보존 여부를 구분한다.

이 선택 기준은 프로젝트의 자체 보완 정책이다. 자세한 기준은 docs/format-policy.md를 참고한다.

## 실행 루프

프로젝트에 설치된 aidocready 버전과 README를 확인한다. 설치된 패키지는 `npx --no-install aidocready`로 실행한다. 저장소에서 개발할 때만 빌드한 `node dist/cli.js`를 사용한다. 배포 패키지 실행에는 src나 개발 의존성이 필요하지 않다. 설치가 필요하면 프로젝트의 lockfile과 검증된 npm 패키지를 사용한다.

1. 원본을 보존하고 작업 사본을 작성한다.
2. `npx --no-install aidocready lint <보고서 절대 경로> --format json --fail-on Warning`을 실행한다.
3. 진단의 ruleId, origin, 위치, coverage와 parserWarnings를 확인한다. 종료 코드 2는 실행 오류를 먼저 해결한다. 검사 불완전이면 통과로 보고하지 않는다.
4. 원문과 대조하며 구조만 수정한다. 수치·단위·날짜·조건·고유명사·사실이 모두 유지되는지 확인한다. 의미 변경이 필요하면 사용자에게 근거를 확인한다.
5. 다시 lint를 실행한다. 같은 진단이 남으면 수정 가능한 구조인지 수동 판단인지 확인한다. 무의미한 수정 반복은 중단하고 남은 사항을 보고한다.
6. 수정 이유, 정적 검사 결과와 수동 검토 사항을 함께 전달한다.

HWPX 작성은 Kordoc 라이브러리의 `markdownToHwpx`를 사용한다. 생성된 HWPX 자체도 lint한다. Markdown 검사만으로 HWPX 결과를 보증하지 않는다. 변환 과정의 수치·구조·내용을 원문과 대조한다.

CLI는 문서를 수정하지 않는다. 의미 검토와 수정은 호스트 에이전트가 수행한다. lint 통과는 공식 인증이나 사실 보존의 보증이 아니다. 문장 명확성, 꾸미기 적절성, 캡션 위치와 복잡한 병합은 사람이 최종 판단한다.
