혼합 문서 사례에는 서술형·표·목록 세 절이 있으므로 32회 응답에 총 40개 절이 포함된다. 일반 초기 연결 확인과 설정 보완 후 확인 호출은 본 실행 점수에 합산하지 않는다. 원래 본 실행의 자동 통합 점수는 29/32였고, 부정 표현의 동등성을 인정하도록 채점기를 고친 뒤 같은 응답을 재채점해 31/32가 됐다. 모델을 다시 호출해 얻은 향상으로 해석하지 않는다.

## 발견한 문제

1. **채점기 표현 오탐:** ‘미확인’을 ‘아직 확인되지 않았다’로 쓴 문장이 사실 누락으로 판정됐다. 명시적 동등 표현을 허용하고, ‘확인됐다’라는 반대 주장은 통과하지 않도록 회귀 테스트를 추가했다. 모델에 제공한 프롬프트와 사실은 바꾸지 않았다.
2. **기존 lint 엔진의 번호 문맥:** Claude의 mixed-report 두 번째 응답은 `## 3. 준비 절차` 아래 `1. 시험 계정 …`, `2. …`, `3. …`을 작성했다. `ADR-NUMBER-SEQUENCE`가 제목 번호와 하위 목록을 같은 단계로 읽어 Warning을 냈다. 형식 선택은 적절하지만 통합 검사는 실패로 유지한다. 이번 작업에서 검사 엔진을 변경하거나 경고를 숨기지 않았다.
3. **선택 이유의 표현:** Claude의 decision-reasons 첫 응답은 화면 개선안과 문자 안내안을 모두 보존했지만 선택 이유에서 ‘비교할 대안이 하나뿐’이라고 표현했다. 실행 가능한 선택안이 하나라는 의미일 수 있어도, 두 대안을 검토한 원문을 정확히 설명하는 표현은 아니다. 문서의 사실 누락이나 형식 실패와 분리해 수동 검토 사항으로 기록한다.
4. **채점기 우회 방지:** 본문에 사실을 모두 놓고 무관한 불릿 하나만 추가하거나, 모든 작업을 번호 항목 하나에 몰아넣는 답은 실패하도록 강화했다. 한 문단 요청도 실제 문단 수로 검사한다. 이 보완 후에도 기존 응답의 형식 점수 40/40은 유지됐다.

## 의미와 한계

비교 자료에서 표를 선택하고, 순서 없는 항목에는 불릿을, 절차에는 번호 목록을, 선택 이유에는 서술형을 선택했다. 용어 설명처럼 애매한 사례는 목록과 표를 모두 허용하며 실제로 Codex의 두 반복에서 서로 다른 형식을 선택했다. 형식의 정답을 무조건 서술형으로 정하지 않았다.

소수의 가상 사례이며 모델 순위·실제 문서 정확도·정책의 인과 효과·공식 준수율을 측정한 결과가 아니다. 핵심 표현·수치·표 행 대응 검사는 사실 보존의 부분적인 보호장치다. 선택 이유와 조건·예외의 의미는 사람의 대조 검토가 필요하다. 출력 원문과 원래 판정은 로컬 results에 보존하며, 인증 정보는 결과에 포함하지 않는다.

재현 방법은 [평가 실행 안내](../evals/format-selection/README.md)를 참고한다. 일반 CI는 유료 SDK 호출을 실행하지 않고 채점기 회귀 테스트만 수행한다.

## 인증 선택 보완

후속 개선에서 구독 로그인 우선, 구독이 없으면 환경 API 키 또는 CLI에 저장된 API 키, 둘 다 없으면 전체 사전 검사 실패로 명시했다. 모델 호출 전에 선택한 제공자 전부를 확인한다. 구독 선택 시 자식 프로세스에서 API 키를 제거하며 부모 환경이나 저장된 로그인을 바꾸지 않는다. 구독 한도·만료 오류를 API 재시도로 숨기지 않는다. 이전 본 실행 점수는 다시 실행한 결과로 바꾸지 않는다.

검증: 잘못된 테스트용 API 값을 부모 환경에 함께 설정한 실제 실행에서 두 SDK 모두 구독을 선택하고 compare-values 사례를 통과했다. [인증 우선순위 실행 기록](../evals/format-selection/evidence/auth-priority-2026-10-10.json)은 인증 방식과 버전·성공 여부만 보존한다. API 키만 있음·인증 없음·확인 실패는 회귀 테스트의 격리된 상태로 검증했으며, 실제 사용자 로그인을 삭제하거나 로그아웃하지 않았다.
