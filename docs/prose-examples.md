# 서술형 예시의 작성과 검증

소개 페이지의 두 서술형 예시는 Codex가 공개 npm aidocready@0.2.0의 SKILL.md 지침을 읽고 작성했다. aidocready CLI가 변환한 결과가 아니다. hwp2md 내장 파서 출력과도 구분한다. 원본·결과·검사 JSON은 site/assets/prose/에 있으며 provenance.json은 공개 버전, 작성 방식, 원문 줄 범위, 공개 SKILL 및 파일 해시와 원문 대조 기록을 담는다.

표 예시의 재구성 전 파일은 기존 변환 파일의 8–17번째 줄 그대로다. 세 분야의 직급·인원·기간·근무지를 각각 서술형으로 연결했고, 원본 HWPX 미리보기에서 확인한 공통 근무지 병합만 풀었다. 세 직위·총 세 명, 각 분야 한 명, 날짜 표기, 근무지, 연장 조건을 보존했다. 소개 화면에는 종무(천주교) 문단만 발췌하고 전체 파일은 다운로드로 제공한다.

열거형 예시는 24번째 줄의 종무(불교) 담당 업무 셀에서 다섯 개 업무를 발췌한 텍스트다. 재구성 전 파일도 원문 셀에서 추출한 발췌이며 변환기 출력의 바이트 동일 복사라고 설명하지 않는다. 분야와 직급은 같은 행에서 확인했다. 다섯 업무를 서술식 문장으로 풀고 주체를 명시했으며 새로운 업무·성과를 추가하지 않았다.

공개 npm 패키지를 별도 설치한 실제 CLI로 네 Markdown 파일을 검사했다. 재구성 후 파일에는 --fail-on Warning도 적용했다. JSON의 file만 다운로드 파일명으로 정규화했다. 표는 Warning 3→0, coverage.complete false→true다. 열거형은 전후 모두 Warning 0, coverage.complete true다. 구조 검사 범위의 변화이며 사실 보존·가독성·AI 검색 정확도를 자동으로 측정한 결과가 아니다.

원문 수치·조건·업무 관계를 대조하고, 고정 예시의 문자열 누락·변경을 회귀 테스트로 검사한다. 이 검사는 일반 문서의 의미 보존을 증명하는 검증기가 아니다. 실제 사용자는 원문을 보존하고 호스트 에이전트로 작성한 뒤 CLI 진단과 원문을 함께 대조해야 한다.

## 갱신

원문·SKILL·엔진 버전을 변경하면 예시와 실제 검사 JSON을 함께 재검증하고 provenance 해시를 갱신한다. 빌더가 source/SKILL/version/파일 해시·진단 합계·고정 예시의 핵심 사실을 점검한다. Pages 배포는 scripts/prose-example-lib.mjs 변경도 감지한다. 새로운 작성 기능이나 자동 변환 CLI를 구현·게시하기 전에는 해당 기능으로 홍보하지 않는다.
